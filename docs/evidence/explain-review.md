# EXPLAIN review (Wave 14, 2026-11-15)

Plan §9.4 and engineering rule 1: every list and report query needs a supporting index. Each statement
below was run on `ecommerce_test` (PostgreSQL 18, migrations through `20261114180000`) inside a
rolled-back transaction with `SET LOCAL enable_seqscan = off`, so the plan shows whether an index **can**
serve the query (on these small tables the planner would otherwise prefer sequential scans, L26).

Result: **26 / 26 queries use an index.** One query was fixed in this review: the dashboard's return
count filtered on `return_requests.created_at` (no index → `Seq Scan`); it now filters on
`requested_at` (written together with `created_at` at insert), served by a skip scan on
`return_requests(status, requested_at)` — `src/modules/reporting/report.repository.ts`. No migration
was needed.
